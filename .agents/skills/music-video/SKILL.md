# 音乐 MV 制作

项目根：仓库根目录（含 `AGENTS.md` 的那一层）。开工前确认当前目录。

## 开工前

1. **先跑 `npm run stage -- <slug>`**。它直接告诉你当前做到哪、缺什么、下一步跑什么。比读五个文件快。
2. 读项目根 `AGENTS.md`（目录契约、数据格式、铁律）。
3. 读 `songs/<slug>/worklog.md` —— 记着已知问题和做过的决定。
4. 跑 `npm run doctor`。有 FAIL 先按 `docs/toolchain.md` 修，不要改技术栈绕过。

**接手时不要重做已完成的步骤。** `stage` 显示 ✓ 的跳过。

## 新歌启动

用户说「做《XX》」「给这首歌做个 MV」时，按这个来，**不要反问"要不要建目录"**。

### 1. 先问清两件事

- 歌名和艺人（决定目录名）
- mp3 和 lrc 在哪

文件路径给了就一条命令；没给就先建空目录，让他放文件。

### 2. 建档（一条命令）

```bash
npm run mv:new -- "歌名-艺人" --audio "D:/Downloads/xx.mp3" --lrc "D:/Downloads/xx.lrc"
```

这一条会：复制模板 → 导入素材并改名 → 填 `song.json` → 直接跑音频分析。

命名规范：`<歌名>-<艺人>`，中间**一个**短横线。不加日期、不加序号、不加来源后缀。
`人生态度-王七七` ✅　`人生态度(1)-王七七-抖音版` ❌

没给文件时：

```bash
npm run mv:new -- "歌名-艺人"
```

然后告诉他：把 mp3 和 lrc 放进 `songs/<slug>/source/`，放好说一声。

### 3. 报结果，重点报三样

分析完直接报：**时长 / BPM / 正文歌词行数**，外加段落切点。

BPM 必须加一句提醒人工核对（算法会给半速或双速）。段落切点偏粗也要说。

### 4. 先问素材，再谈方案

跑 `prompts/00-素材盘点.md`。问六件事：

1. 人物 / 角色有没有指定形象
2. 风格参考有没有「就想要这种感觉」的图
3. 背景 / 场景有没有实拍照片
4. 动态素材有没有要剪进去的视频片段
5. 文字 / logo 有没有必须出现的
6. 每一项的版权状态

有就让用户丢进 `assets/`（`character` / `background` / `reference` / `clip`，不用改名），你负责扫描归类、登记进 `concept/asset-manifest.json`，标 `origin`。

**这一步不要省。** 有没有素材决定整个方案往哪长：
- 有人物设定 → 往角色叙事走
- 有实拍背景 → 往拼贴 / 合成走
- 什么都没有 → 纯代码生成，最可控

**没有素材是正常结果。** 不要为了显得专业硬造一个人物。

### 5. 不停，直接进 Step 2

素材问完就跑 `prompts/01-歌词解读.md`，把 `analysis/structure.md` 的歌词表填进去。
不要问"要不要继续"，用户要的就是往前走。

## 不要做的事

| 别做 | 为什么 |
|---|---|
| 在 `songs/` 根目录散放 mp3/lrc | 会污染目录，`stage` 扫不到，下一首歌更乱 |
| 手工复制 `_template` 建目录 | 漏掉 worklog 占位、song.json 路径、logs/ |
| 跳过 `mv:analyze` 直接写分镜 | 时间是瞎估的，后面全错位 |
| 一次建多首歌的目录 | 一首没做完就开下一首，两首都半途而废 |

## 八步（详见 docs/workflow.md）

| 步 | 做什么 | 产物 | 命令 / 工具 |
|---|---|---|---|
| 0 | 建目录、素材归位 | `song.json` `source/` | `npm run mv:new -- "歌名-艺人"` |
| 1 | 音频分析 | `analysis/audiomap.json` `lyrics.json` `structure.md` | `npm run mv:analyze -- <slug>` |
| 2 | 歌词解读 | `concept/01-歌词解读.md` | `prompts/01-歌词解读.md` + ChatGPT/DeepSeek |
| 3 | MV 概念 | `concept/02-MV概念.md` | `prompts/02-MV概念.md` |
| 4 | 风格定义 | `concept/00-风格定义.md` | `prompts/05-风格定义.md` |
| 5 | 分镜（**需人审**） | `concept/storyboard.json` `03-分镜表.md` | `prompts/03-分镜.md` |
| 6 | 参考图 | `refs/` `concept/prompts/` | `prompts/04-图像提示词.md` + ChatGPT Image |
| 7 | 渲染（Phase 2） | `out/` | `mv:snap` → `mv:render` → `mv:check` |

当前阶段：**Phase 1（0–6）**。渲染代码在 `engines/`，已验证可用但现在不碰。

**四个审核点**：概念、风格、分镜、素材。其余步骤按判据自查推进。批准写进 `song.json` 的 `approvals`，没批准不许进下一步。

## 硬规则

- **风格和形式由人拍板，AI 只给选项**。`prompts/02`（概念）和 `prompts/05`（风格）都是两轮：先出 3 个方案，等人选完才写正文。**不许"我建议 A 所以直接按 A 写下去"** —— 建议可以给，但必须等人回话。
- **每首歌风格必须重写**。`00-风格定义.md` 抄上一首 = 这个项目白做。
- **先定风格再切分镜**。风格卡没写完不要开分镜，否则 20 个镜头出 20 种风格。
- **分镜时间只能来自音频**。`audiomap.json` 的段落边界、`lyrics.json` 的行时间，不许凭感觉估。
- **不改 `analysis/*.json`**。那是算出来的，要调就重跑或改分镜。
- **参考图不进成片**。只用来定色彩和构图，1080p 下 AI 图放大会糊。
- **每完成一步更新 `worklog.md` 和 `song.json` 的 stage**，不要攒着。

## 六项由人拍板的决策

在 Step 3 第一轮一起定，记在 `concept/02-MV概念.md` 的「最终选择」表：

| 决策项 | 可选 |
|---|---|
| 表现形式 | 纯图形 / 单主角 / 文字驱动 / 固定场景 |
| 视觉风格 | 水墨 / 像素 / 极简几何 / 拼贴 / 3D |
| 是否出现人物 | 有 / 无 / 只剪影 |
| 色彩倾向 | 冷 / 暖 / 单色 / 高对比 |
| 节奏 | 快切 / 长镜 / 混合 |
| 画幅 | 竖屏 / 横屏 / 双版本 |

六项没定，不许进 Step 4。`npm run stage` 会查这张表填没填。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 抄上一首的风格卡 | 十首歌长得一样 | 每首重写，禁止清单也要新写 |
| 跳过风格直接写分镜 | 20 个镜头 20 种风格 | 先跑 `prompts/05` |
| 分镜按"每 3 秒一刀"切 | 画面和音乐完全无关 | 用段落边界 + 歌词行 |
| 信算法给的 BPM | 半速/双速，全片错位 | 手打拍子核一遍 |
| 参考图出 10 张再回头 | 风格跑偏要全废 | 先出片头一张定调 |
| `visual` 写"氛围感很强" | 画不出来，等于没写 | 写具体画面：主体 + 动作 + 环境 |
| 音乐名单当歌词 | 片头出现"编曲：某某" | 过滤 `kind === "meta"` |
