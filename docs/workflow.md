# 制作流程

八步。Phase 1 只到第 6 步。

```
source/ ──分析──► analysis/ ──解读──► 01 ──概念──► 02 ──风格──► 00 ──分镜──► storyboard ──出图──► refs/
```

每首歌都是这套骨架，但**内容全部重写**。骨架保证不遗漏，内容保证不雷同。

## 谁做决定

**AI 给选项，人做决定。** 下面六处必须停下来等人回话，其余按判据自查推进。

| 拍板点 | 在哪 | AI 给什么 | 人回什么 |
|---|---|---|---|
| 方向选型 | Step 3 第一轮 | 3 个差异明显的方向 + 六项决策建议 | 「选 B，人物只要剪影」 |
| 概念确认 | Step 3 第二轮 | 完整方案 | 过 / 改哪段 |
| 样式选型 | Step 4 第一轮 | 3 套样式（配色+字体+质感+风险） | 「选 C，配色用 B 的」 |
| 风格确认 | Step 4 第二轮 | 完整规范 | 过 / 改哪条 |
| 分镜 | Step 5 | storyboard.json + 校验结果 | 过 / 改哪个镜头 |
| 素材 | Step 6 | 6–10 张参考图 | 哪张换、哪张定 |

**没回话就不许写正文。** 尤其 Step 3 和 Step 4 —— AI 最容易在这里"贴心地"替你选一个然后写下去。

批准写进 `song.json`：

```json
"approvals": { "concept": { "by": "人", "at": "2026-10-21" } }
```

六项决策（Step 3 第一轮一起定，记在 `02-MV概念.md` 的「最终选择」表）：

```
表现形式：纯图形 / 单主角 / 文字驱动 / 固定场景
视觉风格：水墨 / 像素 / 极简几何 / 拼贴 / 3D
是否出现人物：有 / 无 / 只剪影
色彩倾向：冷 / 暖 / 单色 / 高对比
节奏：快切 / 长镜 / 混合
画幅：竖屏 / 横屏 / 双版本
```

这六项没定，不许进 Step 4。

## Step 0 · 素材归位

**方式一：一条命令（推荐）**

```bash
npm run mv:new -- "人生态度-王七七" --audio "D:/Downloads/人生态度.mp3" --lrc "D:/Downloads/人生态度-王七七.lrc"
```

建目录 + 导入素材（自动改规范名）+ 填 `song.json` + 直接跑分析，一条走完。

**方式二：先建目录再放文件**

```bash
npm run mv:new -- "人生态度-王七七"
```

然后手工两件事：

1. mp3 和 lrc 放进 `source/`，文件名尽量短：`人生态度.mp3`、`人生态度-王七七.lrc`。
2. 打开 `song.json` 填 `source.audio` / `source.lrc`（相对歌曲目录的路径）。

**不要手工复制 `_template` 建目录**，会漏掉 `worklog.md` 的占位、`logs/`、`song.json` 的路径字段。

**完成判据**：`npm run stage -- <slug>` 的第 0 项显示 ✓。

**LRC 从哪来**：网易云/QQ音乐客户端能导出；没有就搜"歌名 lrc"。实在没有，Step 1 会跳过歌词解析，但歌词 MV 必须有 LRC，没有就先解决这个。

## Step 0.5 · 素材盘点

**在建完目录之后、写任何方案之前。** 跑 `prompts/00-素材盘点.md`，问六件事：

1. 人物 / 角色有没有指定形象
2. 风格参考有没有「就想要这种感觉」的图
3. 背景 / 场景有没有实拍照片
4. 动态素材有没有要剪进去的视频片段
5. 文字 / logo 有没有必须出现的
6. 每一项的版权状态

素材全部丢进 `songs/<歌>/assets/`，不用改名：

```
assets/character/    人物、立绘、三视图
assets/background/   背景、场景、实拍
assets/reference/    风格参考、截图、色板
assets/clip/         视频片段、GIF、序列帧
```

AI 负责扫描、归类、登记进 `concept/asset-manifest.json`。

**为什么要先做**：有没有素材决定整个方案往哪长。有人物就往角色走，有实拍就往拼贴走，什么都没有就走纯代码生成。这三条路的分镜和风格完全不同，做到一半才发现"我这有素材"，等于返工。

**完成判据**：能回答一句话 —— **画面里有多少是现成的，有多少是画出来的。**

没有素材也是正常结果，不用勉强准备。多数歌根本不需要人物。

## Step 1 · 音频分析

```bash
npm run mv:analyze -- 人生态度-王七七
```

做三件事：

1. `ffmpeg` 把 mp3 转 `44.1k / mono / s16` 的 wav（放 `analysis/_source.wav`，不动 `source/`）。
2. 算逐帧能量包络 + BPM + onset → `audiomap.json`。
3. 解析 LRC → `lyrics.json`（制作信息标记为 `meta`），同时生成人读的 `structure.md`。

**完成判据**：`structure.md` 能看懂；时长和实际一致；歌词行数合理。

**必做的两处人工核对**：

- [ ] **BPM 对不对**。跟着歌用手打拍子数 15 秒，算 `拍数 / 15 × 60`，和输出的 BPM 比。差一倍说明算法锁到了半速或双速。
- [ ] **段落切分合不合理**。看 `structure.md` 的「能量段落」表，对着歌听一遍这几个时间点。如果 60 秒内没有任何切分，多半漏了，分镜时按歌词行补。

分析结果**不要手工改**。BPM 错了就在分镜里全用 `phrase_flow`，不要改 JSON 里的数字。

## Step 2 · 歌词解读

打开 `prompts/01-歌词解读.md`，复制整段，把 `{{...}}` 换成实际内容（歌词从 `structure.md` 的歌词时间轴粘）。

产出粘到 `concept/01-歌词解读.md` 对应小节下。

**这一步只做理解，不做设计。** 不要在解读阶段就开始想画面，会把歌词压成俗套。

**完成判据**：

- [ ] 「一句话主题」是动作或状态，不是"表达了……的情感"
- [ ] 「视觉母题」5 条，每条都能想象出具体构图
- [ ] 「禁区」5 条是具体画面，不是"不要低俗"这种废话

不满足就让模型重写那一节，不用整段重来。

---

## Step 3 · MV 概念（两轮）

`prompts/02-MV概念.md`，输入是 Step 2 的全文 + `structure.md` 的段落表。

**第一轮只给选项**：3 个差异明显的方向 + 六项决策建议 + 每个方向的风险。
你回一句话选定（可以混搭），它才进第二轮。

**第二轮写完整方案**：logline / 世界观 / 叙事推进 / 色彩剧本 / 运动语言 / 三个必现画面 / 禁区。

**这一轮不许跳。** 概念定的是"这支片子长什么样"，改一次等于重做分镜。

**完成判据**：

- [ ] `02-MV概念.md` 的「最终选择」表填完了
- [ ] Logline 一句话能说给别人听
- [ ] 世界观里能读出材质（"宣纸"而不是"梦幻"）
- [ ] 色彩剧本的段落数 = 音频段落数
- [ ] 三个必须画面里至少有一个是反直觉的

**关键自检**：这个方案换一首同类型的歌还成立吗？成立就重做。好方案只对这首歌成立。

---

## Step 4 · 风格定义（两轮）

`prompts/05-风格定义.md`，输入是 Step 3 的全文。

**这一步是整个项目最容易做废的地方。** 每首歌必须重写，不能抄上一首。

**第一轮给 3 套样式**，每套只写七行：一句话 / 色板 / 字体 / 质感 / 光线 / 最适合 / 风险。
三套必须是三种审美路线，不是同一套换颜色。

你选一套，或者混搭（「配色用 B，字体用 C」）。选完才进第二轮。

**第二轮写完整规范**，并回填 `song.json`：

```json
"style": {
  "palette": ["#0B0B0C", "#C8A24A", "#8C2F27", "#E8E2D4"],
  "font": "楷体",
  "texture": "宣纸纤维 0.6 + 颗粒 0.2",
  "lighting": "顶光偏冷，边缘暖金反光"
}
```

**完成判据**：

- [ ] 「样式候选」里有 3 套，「选定」填了
- [ ] 色彩 ≤ 6 个，有十六进制，有占比
- [ ] 一句话调性是"像 ______ 的 ______"，参照物具体
- [ ] 禁止清单 6 条，具体到颜色和元素
- [ ] `song.json` 的 `style` 回填了
- [ ] `approvals.style` 记了一笔

**判断标准**：把这张卡给一个没听过歌的人，他能画出风格接近但内容不同的画面。

---

## Step 5 · 分镜（唯一需要人审的一步）

`prompts/03-分镜.md`，输入是风格卡 + 概念 + 音频结构 + 歌词时间轴。

### 切镜硬规则

1. 段落边界（`structure.md` 的 lift/drop）必切
2. 一镜 = 1–3 句歌词
3. 副歌镜头比主歌短 30% 以上
4. 前奏和间奏用空镜，不硬塞歌词
5. 3 分钟的歌，20–32 个镜头

### 产出

- `concept/storyboard.json`（给程序读，格式见 `songs/_template/concept/storyboard.example.json`）
- `concept/03-分镜表.md`（给人看，表格）

### 机器先筛一遍

```bash
npm run mv:validate -- <slug>
```

查：时间轴连续性、越界、缺字段、id 重复、歌词覆盖、段落边界、`visual` 里的空洞词、`refs` 指向的图是否存在。

`ERROR` 必须改，`WARN` 自己判断。**校验不过不要进人审**，省得人看一堆格式问题。

### 人审清单

- [ ] 每句歌词都落在某个镜头的 `lyrics` 里
- [ ] 相邻镜头首尾相接，总时长 = 全曲时长
- [ ] 情绪最高点镜头元素最多，最低点有静止镜头
- [ ] 没有连续三个镜头构图雷同
- [ ] `visual` 里没有"氛围感/情绪/张力/唯美/梦幻"这类词

**不过不要往下走。分镜错了后面全白做。**

## Step 6 · 参考图

`prompts/04-图像提示词.md`，挑 6–10 个关键镜头出图。

- 每个段落的第一镜（定调）
- 情绪最高点、最低点
- 最难画的那 1–2 个
- 片头/片尾

图和提示词同名同序号：`refs/01-墨山.png` + `concept/prompts/01-墨山.md`。

**顺序很重要**：先出片头那张。不满意就改风格卡，不要往下出十张再回头。

**完成判据**：

- [ ] 6–10 张，放在一起看色调一致
- [ ] 没有一张出现禁止清单里的东西
- [ ] 没有一张是明显不同的风格
- [ ] 每张都有对应的提示词文件
- [ ] `concept/asset-manifest.json` 已登记（id / type / path / prompt / source / status / usedIn）

`refs/` 里的图**不进成片**，只用来定色彩构图、给 AI 编码工具看感觉。

### 为什么要有 asset-manifest

出到第三首歌你就会忘：这张图是给哪个镜头出的、用哪个提示词、哪版是定的。
manifest 是唯一记录。渲染时程序按 `usedIn` 找图，不靠文件名猜。

`type` 字段区分 `style-board` / `character` / `background` / `keyframe` / `clip`，不用建一堆空目录。

## 横竖屏怎么处理

一首歌的分析、解读、分镜只有一份，**构图参数两套**。

`song.json` 的 `format` 里 `portrait` 和 `landscape` 各自有宽高帧率；分镜里如果要区分，就加 `composition`：

```json
"composition": {
  "portrait": { "focusX": 0.5, "focusY": 0.42, "scale": 1.25 },
  "landscape": { "focusX": 0.5, "focusY": 0.5, "scale": 1.0 }
}
```

**不要靠裁切或旋转做竖屏**。横屏里人在左边的构图，竖屏直接裁会把人切掉一半，得靠 `focusX/scale` 重新取景。Phase 1 可以只填 `portrait`，等真要出双版本再补。

---

## Step 7 · 渲染（Phase 2）

现在不做。等分镜定稿、参考图出齐之后再来。

届时：

```bash
npm run mv:snap   -- <slug> --times 5,30,60,90,120   # 抽帧看效果
npm run mv:render -- <slug> --workers 6              # 全片
npm run mv:check  -- <slug>                          # 质检
```

引擎三选一（`song.json` 的 `engine`）：`canvas` 自建 / `hyperframes` HTML / `remotion` React。
详见 `docs/toolchain.md` 第五节。

## 返工对照表

| 症状 | 改哪 | 不要动 |
|---|---|---|
| 歌词理解偏了 | `01-歌词解读.md` 的「一句话主题」和母题 | 分镜 |
| 整体感觉不对但说不出 | `00-风格定义.md` 的「一句话调性」 | 分镜 |
| 参考图风格散 | 风格卡 + 重出 | 分镜 |
| 分镜太平 | 检查副歌镜头是不是够短、最高点元素是不是最多 | 风格卡 |
| 某句歌词没画面 | 那个 shot 的 `visual` | 其他镜头 |
| 时间对不上 | 重跑 `mv:analyze`，检查 LRC | 分镜数字 |
